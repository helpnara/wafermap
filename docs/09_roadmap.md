## M5.5 — 도메인 보강 (다음 작업) ★

첨부해 주신 EDS 상세 정리 문서와 현재 코드를 대조해 찾은 공백입니다.
**데이터층부터 위로** 진행해야 재작업이 없습니다.

### ① 검사 장비 축 추가 — Prober / Probe Card / ATE

**왜 먼저 해야 하나**: 지금 데이터 모델에는 **검사 장비가 아예 없습니다.**
프로브 카드 접촉 불량은 Edge/Ring 패턴을 만들지만 **공정 문제가 아닙니다.**
"이게 팹 문제냐 테스트 문제냐"를 가르는 축이 없어서, 현재 분석은 구조적으로
**항상 공정을 범인으로 지목**합니다. 나중에 넣으면 M1 데이터 재생성이 필요합니다.

- `wafer_master`에 `tester_id`, `probe_card_id`, `probe_touchdown_count` 추가
- 프로브 카드 니들 마모 → Edge 패턴을 만드는 기전을 시뮬레이터에 심기
- 커미널리티 검정 단위에 검사 장비 포함 → "공정 챔버 vs 프로브 카드" 경쟁 검정
- **채점 항목 추가**: 테스트 기인 불량을 공정 탓으로 오판하지 않는가

### ② 센서 시계열 파생 피처 — slope / peak / time-above-threshold

**왜**: 첨부 문서 §12가 든 예가 정확히 현재의 맹점입니다.
평균 500℃인데 30~31초 구간만 540℃ — **평균·표준편차로는 안 보입니다.**
`fdc_trace.parquet`(151,200행)은 이미 만들어 뒀는데 거기서 뽑는 피처가 없습니다.

- `features/trace_feat.py` 신설 — slope, peak, time_above_threshold, 구간 변화량
- 시뮬레이터에 **스파이크형 이상** 추가 (요약통계로는 안 잡히는 유형)
- **측정**: 스파이크 기인 불량에서 M4 검출력이 실제로 오르는가

### ③ 공정 간 교호작용 분석 — SHAP interaction + 장비 조합

**왜**: 첨부 문서가 §14·15·16·21·37과 대시보드 화면 6까지 배정한 주제인데
**코드에 전혀 없습니다.** 문서 §42의 차별화 메시지가 바로 이 부분입니다.

- `analysis/interaction.py` — `shap_interaction_values()` 기반 파라미터 A×B
- **선행 장비 × 후행 장비** 조합 검정 ("B가 문제"가 아니라 "A→B 조합에서 증가")
- 증착 두께 × 식각 조건 같은 **스텝 간** 교호작용을 시뮬레이터에 심고 채점
- 화면 추가: 교호작용 히트맵

### ④ Die 단위 측정값과 Bin 부여

**왜**: 첨부 문서 §4·11.1이 "EDS는 Die 단위 **전기적 측정 데이터**를 만든다"를
핵심으로 강조하는데, 현재는 die별 pass/fail 이진값뿐입니다.
`BIN_CODES`는 `config.py`에 정의만 해 두고 아무 데서도 쓰지 않습니다.

- die별 Test Item / Measurement(연속값) 생성 → 임계로 Bin 부여
- Bin별 웨이퍼 맵(불량 유형별 색 구분) — 화면 2에서 활용
- 우선순위는 가장 낮음 (분석 결론이 바뀌지 않고 화면이 풍부해지는 수준)
