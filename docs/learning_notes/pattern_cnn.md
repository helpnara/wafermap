# 경량 CNN — 피처를 사람이 만들지 않으면 어떻게 되나

## 이 코드는 무엇을 하나

**입력**: wafer map을 64×64×2채널 이미지로 변환한 것
**출력**: 9종 패턴 중 하나 + Grad-CAM 열지도(모델이 본 영역)

LightGBM은 사람이 설계한 121개 피처를 먹는다. CNN은 **이미지를 그대로** 먹고
필요한 피처를 스스로 만든다. 같은 문제를 정반대 방향에서 푸는 셈이다.

> 성능을 더 올리려고 만든 게 아니다. LightGBM이 이미 macro-F1 0.97을 낸다.
> **두 접근의 성격 차이를 근거를 갖고 이야기하기 위해** 만든 비교군이다.
> 실제로 측정해 보니 CNN이 더 나쁘고 더 느렸다 — 그 결과 자체가 결론이다(아래 참조).

## 핵심 로직

### 1단계: 왜 채널을 2개로 나누나 ★

가장 먼저 결정해야 할 것은 "0/1/2를 어떻게 넣을 것인가"다.
그냥 넣으면 안 된다.

```python
    die = (wafer != DIE_NONE).astype(np.float32)
    fail = (wafer == DIE_FAIL).astype(np.float32)
```

```
❌ 1채널에 0/1/2 그대로              ✅ 2채널로 분리 (채택)
                                     
 die 없음 = 0                         채널0 (die 마스크):  0 또는 1
 pass    = 1                          채널1 (불량 마스크): 0 또는 1
 fail    = 2                          
                                      "die 없음"과 "pass"는
 conv은 이 값들을 숫자로 더한다        채널0에서만 구분되고,
    ↓                                 "pass"와 "fail"은
 "0과 1의 차이"와 "1과 2의 차이"가     채널1에서만 구분된다
 같은 크기로 취급됨                       ↓
    ↓                                 두 구분이 섞이지 않는다
 웨이퍼 **밖** 영역이 불량처럼
 학습에 끼어든다
```

웨이퍼 바깥(0)은 "die가 없는 곳"이지 "아주 좋은 die"가 아니다.
1채널로 넣으면 conv 필터가 이 둘을 연속적인 값으로 오해한다.

### 2단계: 리샘플링은 최근접 이웃으로

```python
    ri = np.clip((np.arange(size) * rows / size).astype(int), 0, rows - 1)
    ci = np.clip((np.arange(size) * cols / size).astype(int), 0, cols - 1)
```

선형 보간(bilinear)을 쓰지 않는다. die 격자는 **이산 구조**라서,
pass(0)와 fail(1) 사이를 보간하면 0.5라는 **존재하지 않는 상태**가 생긴다.

### 3단계: 신경망 구조

```python
    return nn.Sequential(
        block(2, 16, n_conv=1),   # 64 → 32
        block(16, 32),            # 32 → 16
        block(32, 64),            # 16 → 8
        block(64, 96),            # 8 → 4   ← Grad-CAM이 참조하는 마지막 conv
        nn.AdaptiveAvgPool2d(1),
        nn.Flatten(),
        nn.Dropout(0.3),
        nn.Linear(96, n_classes),
    )
```

해상도를 절반씩 줄이면서 채널을 늘려 간다. 이건 CNN의 표준 패턴이다.

```
64×64×2  ──▶ 32×32×16 ──▶ 16×16×32 ──▶ 8×8×64 ──▶ 4×4×96 ──▶ 96 ──▶ 9
 원본        "인접한        "링/덩어리    "형상"      "패턴"    GAP   클래스
             불량"          구조"
 해상도 ↓ (위치 정보 감소)          채널 ↑ (의미 정보 증가)
```

**Global Average Pooling**(`AdaptiveAvgPool2d(1)`)을 쓰는 이유는 두 가지다.

1. `Flatten`(4×4×96 = 1,536 → 9)보다 파라미터가 훨씬 적어 과적합이 덜하다
2. **Grad-CAM이 성립하려면** 마지막 conv의 공간 정보가 살아 있어야 한다

### 4단계: Grad-CAM — "모델이 어디를 봤나"

```python
    handle = model[3].register_forward_hook(hook)
```

`register_forward_hook`은 순전파 도중 특정 층의 출력을 **가로채는** 장치다.
`model[3]`은 마지막 conv 블록이다.

동작 순서는 이렇다.

```
1. 순전파 → hook이 마지막 conv 출력(4×4×96)을 붙잡는다
2. 예측 점수를 역전파 → 그 출력에 대한 기울기(4×4×96)를 얻는다
3. 기울기를 공간 방향으로 평균 → 채널별 중요도 (96개 숫자)
4. 중요도로 특징 지도를 가중합 → 4×4 열지도
5. ReLU + 64×64로 확대
```

```python
        weights = grads.mean(dim=(2, 3), keepdim=True)  # 채널별 중요도
        cam = torch.relu((weights * feature_map).sum(dim=1, keepdim=True))
```

**직관**: "이 채널의 값이 커지면 예측 점수가 올라가는가?"를 기울기로 묻고,
그렇다고 답한 채널들이 강하게 반응한 **위치**를 모아 보여 준다.

`torch.relu`를 씌우는 이유는, 음수는 "그 클래스가 **아니라는** 근거"라서
"어디를 보고 그렇게 판단했나"라는 질문의 답으로는 부적절하기 때문이다.

```
                  LightGBM         CNN        차이
  ----------------------------------------------
  macro-F1          0.9741      0.9458   -0.0283
  학습 시간            9.3초      959.0초    103배

  클래스            LGBM F1    CNN F1        차이
  --------------------------------------------
  Scratch          0.883     0.707    -0.176   ← 격차가 여기 몰려 있다
  Loc              0.911     0.868    -0.043
  Edge-Loc         0.994     0.962    -0.033
  none             0.999     0.996    -0.003
  Center           0.980     0.980    -0.000
  Donut/Edge-Ring/Near-full/Random  둘 다 1.000
```

### 격차의 87%가 Scratch 한 클래스에서 나왔다 ★

이건 우연이 아니다. 이유를 짚어 보면 이 프로젝트의 핵심 교훈이 나온다.

| | LightGBM | CNN |
|---|---|---|
| Scratch를 어떻게 아나 | **Radon 변환 피처** — "여러 각도에서 투영했을 때 한 각도에서만 뾰족해지는가"라는 선형 구조의 수학적 정의를 사람이 넣어 줌 | 41장의 예시에서 스스로 알아내야 함 |
| 표본 수 | 41장으로 충분 (피처가 이미 답을 알고 있으므로) | 41장으로는 부족 |

> **데이터가 적을 때는 도메인 지식을 넣은 피처가 종단간 학습을 이긴다.**
> 딥러닝이 피처 엔지니어링을 대체한다는 통념은 데이터가 충분할 때의 이야기다.
> Scratch 41장, Near-full 5장 같은 상황에서는 정반대다.

### Grad-CAM은 잘 작동했다

모델이 실제로 불량 영역을 보는지 정량 검증한 결과다.

```
  ✅ Center      불량영역 CAM=0.589  정상영역 CAM=0.570  비율=1.03x
  ✅ Edge-Ring   불량영역 CAM=0.590  정상영역 CAM=0.485  비율=1.22x
  ✅ Loc         불량영역 CAM=0.655  정상영역 CAM=0.489  비율=1.34x
  ✅ Scratch     불량영역 CAM=0.677  정상영역 CAM=0.517  비율=1.31x
  ✅ Donut       불량영역 CAM=0.730  정상영역 CAM=0.653  비율=1.12x
```

5개 패턴 모두 불량 영역의 CAM 값이 정상 영역보다 높다. 즉 모델은
**엉뚱한 곳을 보고 우연히 맞힌 게 아니다.**

Center의 비율이 1.03으로 낮은 것도 해석이 된다. Center는 불량이 웨이퍼 중앙에
넓게 퍼져 있어 "불량 영역"과 "모델이 보는 영역"이 거의 겹치기 때문이다.

## 왜 이렇게 만들었나 — 설계 선택과 대안

### 선택 1: 왜 첫 블록만 conv 1회인가? — 실제로 측정해서 바꾼 부분

처음에는 4개 블록 모두 conv를 2회씩 넣었다. 그런데 학습이 너무 느렸다.

```
측정: 4,800장 1 epoch = 34초
  → 5-fold × 25 epoch + 최종 학습 = 약 85분
```

연산량은 **(해상도² × 채널수)** 에 비례한다. 64×64는 이 신경망에서 해상도가
가장 높은 지점이라, 여기서 conv를 두 번 하면 전체의 절반 가까이를 차지한다.
반면 초반 층이 배우는 것은 "불량 die가 인접해 있는가" 정도의 저수준 특징이라
층을 겹칠 실익이 작다.

첫 블록을 conv 1회로 바꾼 결과:

```
34초 → 10.6초 (3.2배 단축), 파라미터 209,721개는 그대로
```

이건 성능을 포기한 타협이 아니라, **연산이 어디에 쓰이는지 측정하고 가장 값싼
곳을 고친** 것이다. 대부분의 CNN이 초반에 빠르게 다운샘플하는 것도 같은 이유다.

> 💡 최적화는 추측이 아니라 측정에서 시작한다. "어디가 느린가"를 재기 전에
> 고치면, 전체의 5%를 차지하는 부분을 2배 빠르게 만들고 뿌듯해하게 된다.

### 선택 2: CNN의 진짜 비용 — CPU로는 실측 데이터를 못 돌린다

| | 합성 6,000장 (실측) | 실측 172,950장 (추정) |
|---|---|---|
| LightGBM | **9.3초** | 약 5분 |
| CNN (CPU) | **959초 (16분)** | 약 8시간 |
| 배율 | **103배** | — |

CNN은 CPU에서 실측 데이터를 학습하기에 현실적이지 않다. GPU가 필요하다.
이건 포트폴리오에서 숨길 게 아니라 **명시할 트레이드오프**다.

> 설계서 §4.3이 "클라우드에서는 추론만"이라고 정한 이유가 여기 있다.
> 학습은 오프라인에서 미리 하고, 앱은 저장된 모델을 읽기만 한다.

### 선택 3: 왜 LightGBM과 똑같은 CV 방식을 쓰나?

```python
    skf = StratifiedKFold(n_splits=n_splits, shuffle=True, random_state=seed)
```

fold 분할 방식, 시드, 평가 지표(macro-F1), 클래스 가중치까지 전부 맞췄다.
하나라도 다르면 "CNN이 더 좋다/나쁘다"는 비교가 성립하지 않는다.
**비교하려면 비교 대상 외의 모든 조건을 고정해야 한다.**

`CVReport` 데이터클래스를 `pattern_lgbm`에서 import해 재사용하는 것도 같은 이유다.
두 모델이 문자 그대로 같은 형식으로 결과를 낸다.

## 확인 문제

**1.** wafer map을 1채널(0/1/2)로 넣으면 구체적으로 무엇이 잘못되는가?

<details><summary>정답</summary>

conv 필터는 입력을 **연속적인 숫자**로 다룬다. 1채널이면 "die 없음(0) → pass(1)"의
간격과 "pass(1) → fail(2)"의 간격이 똑같이 1로 취급된다.

그 결과 웨이퍼 **바깥 영역**(값 0)이 "아주 좋은 die"처럼 해석되어,
웨이퍼 경계 부근에서 실제로는 없는 밝기 변화(gradient)를 만들어 낸다.
Edge-Ring처럼 경계가 중요한 패턴에서 특히 해롭다.
</details>

**2.** Grad-CAM에서 `torch.relu`를 빼면 열지도가 어떻게 달라지는가?

<details><summary>정답</summary>

음수 기여도까지 표시된다. 음수는 "이 영역은 그 클래스가 **아니라는** 근거"라는
뜻이라, "어디를 보고 Edge-Ring이라 판단했나"라는 질문의 답으로는 맞지 않는다.
열지도가 지저분해지고 해석이 어려워진다.
</details>

**3.** 마지막 conv가 4×4인데 이걸 64×64로 확대해서 보여 준다. 이 해상도의 한계는?

<details><summary>정답</summary>

열지도의 **실질 해상도는 4×4**이고, 확대는 보간일 뿐이다. 즉 "웨이퍼의 우측 상단
사분면을 보았다" 수준까지는 알 수 있지만 "정확히 이 die를 보았다"는 말할 수 없다.

더 앞쪽 conv를 쓰면 해상도는 올라가지만(8×8, 16×16) 그 층은 아직 저수준 특징만
담고 있어 "패턴 판정 근거"로서의 의미가 약해진다. 해상도와 의미 사이의 트레이드오프다.
</details>

**4.** CNN과 LightGBM 중 현업에 배포한다면 어느 쪽이고, 그 이유는?

<details><summary>정답</summary>

정답이 하나는 아니지만, 이 프로젝트의 맥락에서는 **LightGBM**이 유리하다.

1. **해석**: SHAP으로 "최외곽 링 불량률이 높아서 Edge-Ring으로 판정"이라고
   엔지니어에게 설명할 수 있다. Grad-CAM은 "여기를 봤다"까지만 말한다
2. **비용**: 학습 9초 vs 21분, 모델 4MB vs 0.8MB지만 추론 환경 요구가 다르다
3. **재학습**: 신제품이 들어오면 자주 재학습해야 하는데 CPU로 가능하다

반대로 CNN이 유리한 경우는 **새로운 패턴이 계속 생기고 사람이 피처를 설계하기
어려울 때**다. 우리 피처는 9종 패턴을 겨냥해 만들어졌으므로, 10번째 패턴이
등장하면 피처부터 다시 설계해야 한다. CNN은 데이터만 주면 된다.
</details>
