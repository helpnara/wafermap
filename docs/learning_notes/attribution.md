# 원인 파라미터 규명 — "그 챔버의 무엇이 문제인가"

## 이 코드는 무엇을 하나

**입력**: M3가 특정한 스텝/챔버 + 그 스텝의 FDC 파라미터들
**출력**: 파라미터별 기여도 랭킹과 권고 운전 구간

```
✅ susceptor_temp_mid_delta_mean [조작가능] |SHAP|=1.0534 ↑  Δ=+1.28σ  δ=+0.59
```

## 왜 이 단계가 필요한가

**"어느 챔버"까지 알아도 아직 조치할 수 없다.**

```
M3 결과: "ETCH-B/ch2가 유력하다"           → 장비를 세울 순 없다
M4 결과: "그 챔버의 edge_ring_rf_hours가    → PM 주기를 단축한다
          412시간으로 평소보다 높다"
```

그리고 현업에서는 **설명하지 못하는 모델은 채택되지 않는다.** 장비를 세우거나
설정을 바꾸는 데는 비용이 들고, "AI가 그렇대요"로는 결재가 나지 않는다.
그래서 예측 정확도보다 **기여도 분해**가 이 단계의 본체다.

## 핵심 로직

### 순서가 중요하다 — AUC부터 본다

```python
    if result.auc < 0.7:
```

**AUC가 0.5 근처면 SHAP을 볼 필요가 없다.** 모델이 아무 신호도 못 잡았다는 뜻이므로,
그 위에서 계산한 기여도는 노이즈를 분해한 것에 불과하다.

실제로 Donut 패턴에서 이 상황이 나왔다. 불량이 19장뿐이라 처음엔 AUC 0.698이었고,
챔버 층화 후 0.863으로 올랐다.

| | AUC | 해석 |
|---|---|---|
| 층화 전 | 0.698 | 신호가 약하다. SHAP 해석에 주의 |
| 층화 후 | 0.863 | 챔버 baseline 차이를 제거하니 신호가 선명해짐 |

### 왜 `_mean`과 `_std`만 쓰나

```python
    cols = [
        c for c in fdc_step.columns
        if c not in ID_COLUMNS and c.endswith(suffixes)
    ]
```

한 스텝의 요약 통계는 `_mean/_std/_min/_max` 4종이 있다. 네 개를 다 넣으면
서로 강하게 상관되어 **SHAP 기여도가 분산된다.**

압력이 원인일 때 `chamber_pressure_mean`과 `_max`가 기여를 반씩 나눠 가지면
둘 다 순위가 밀려 진짜 원인을 놓칠 수 있다. `_mean`이 대표성이 가장 높고,
`_std`는 '안정성'이라는 다른 정보를 담으므로 이 둘만 쓴다.

### 계측값 함정 — 이 프로젝트에서 실제로 걸린 것 ★★

Donut 불량을 분석했더니 SHAP 1위가 이렇게 나왔다.

```
1위: thickness_sigma_mean          |SHAP|=1.5298   ← 정답 아님
2위: susceptor_temp_mid_delta_mean |SHAP|=1.0534   ← 정답
```

**틀린 결과가 아니다.** 물리적으로 이어져 있다.

```
서셉터 온도 편차 ↑  →  증착 두께 산포 ↑  →  Donut 불량
   (원인)               (결과)              (증상)
      ↑                     ↑
 여기를 고쳐야 함      SHAP은 여기가 더 강하다고 말함
```

계측값은 원인보다 **불량에 더 가까운 위치**에 있어 신호가 더 선명하다.
그런데 문제가 있다.

> **두께 산포는 조작할 수 없다.** "두께 산포를 줄이세요"는 조치가 아니다.
> 그걸 만들어 내는 온도를 잡아야 한다.

그래서 파라미터에 **역할(role)** 을 붙였다.

| role | 의미 | 예시 |
|---|---|---|
| `control` | 엔지니어가 **직접 조작**하는 설정값 | 온도, 압력, 유량, RF 파워 |
| `measurement` | 공정의 **결과로 측정**되는 값 | 두께, 두께 산포, 선폭, 파티클 수 |

```python
    return [e for e in evidence if e.is_controllable]
```

계측값을 걸러내자 순위가 바로잡혔다.

```
전체 Top-1 적중률:      67% (4/6)
조작 가능만 Top-1:      83% (5/6)   ← Donut이 정답으로 바뀜
```

> 💡 계측값이 상위라는 사실 자체도 **유용한 정보**다. "그 계측값을 만들어 내는
> 상류 파라미터를 찾으라"는 신호이기 때문이다. 버리는 게 아니라 **구분**하는 것이다.

### 모델과 독립적인 증거 — 분포 비교

SHAP은 **모델이 학습한 것**을 설명한다. 모델이 과적합했거나 엉뚱한 신호를 잡았다면
SHAP도 그것을 충실히 설명할 뿐이다.

그래서 모델을 거치지 않고 데이터를 직접 보는 지표를 함께 계산한다.

```python
    greater = (case[:, None] > control[None, :]).sum()
    less = (case[:, None] < control[None, :]).sum()
    total = len(case) * len(control)
    return float((greater - less) / total)
```

**Cliff's delta**는 "불량군의 값이 정상군보다 큰 쌍의 비율 − 작은 쌍의 비율"이다.
범위는 -1~1이고, 순위만 보므로 **이상치에 강건하고 단위가 없다.**

FDC 파라미터는 단위가 제각각(psi, degC, sccm)이라 무단위 지표가 필요하다.

두 결과가 일치하면 신뢰도가 크게 올라간다.

```
✅ susceptor_temp_mid_delta_mean  |SHAP|=1.0534  Δ=+1.28σ  δ=+0.59
   └ SHAP도 높고, 분포도 실제로 다르다 → 신뢰할 만하다
```

### dependence 곡선 — 개선안의 직접 근거

기여도 순위만으로는 "무엇이 문제인가"까지만 알 수 있다.
**"어디까지 허용할 것인가"** 는 다른 질문이다.

```python
    edges = np.unique(np.quantile(values, np.linspace(0, 1, n_bins + 1)))
```

분위수로 구간을 나눈다(값 분포가 치우쳐 있어도 각 구간에 표본이 고르게 들어간다).
그리고 구간별 평균 SHAP과 불량률을 본다.

실제 결과:

```
구간                    평균 SHAP    표본    불량률
-2.08 ~ -1.08            -0.905      42      0%
-0.60 ~ -0.47            -0.462      41      2%
 0.05 ~  0.25             0.040      41      0%
 0.25 ~  0.59             0.436      42      2%   ███
 0.59 ~  2.83             4.911      42     38%   ███████████████████████
                                                   ↑ 여기서 급증
```

**0.59를 넘으면 불량률이 38%로 치솟는다.** 그 아래는 0~2%다.

이제 구체적인 제안이 나온다: *"서셉터 중간대 온도 편차를 0.35 이하로 관리하라."*

### Scratch는 왜 틀렸나 — 정직하게

`pad_life`(CMP 패드 수명)가 1위인데 정답은 `slurry_flow` 계열이다.

원인은 **시간적 교락**이다.

```
pad_life는 톱니파 — 쓸수록 증가하다 PM 때 0으로 리셋
   ↓
시간과 직접 연관된 변수다
   ↓
Scratch 이상 사건이 특정 기간에 몰려 있으면
그 기간의 pad_life 값도 특정 구간에 몰린다
   ↓
모델이 "pad_life가 이 구간이면 불량"을 학습한다
```

**소모품 누적 사용량처럼 시간과 함께 변하는 변수는, 시간적으로 몰린 이상 사건과
자연스럽게 상관된다.** 층화로도 제거되지 않았다(챔버를 고정해도 시간은 남는다).

실무적으로는 Top-5 안에 정답이 있으면 충분하다 — 엔지니어는 상위 후보를 다 확인한다.
하지만 **자동 판정을 그대로 믿으면 안 된다**는 근거이기도 하다.

## 왜 이렇게 만들었나 — 설계 선택과 대안

### 선택 1: 왜 챔버로 층화하나?

M3가 이미 진범 챔버를 찾았으므로 그 챔버 안에서만 분석할 수 있다.
챔버 간 baseline 차이가 제거되어 신호가 선명해진다.

| 패턴 | 층화 전 AUC | 층화 후 AUC |
|---|---:|---:|
| Donut | 0.698 | **0.863** |
| Center | 0.940 | **0.974** |
| Edge-Ring | 0.946 | 0.950 |

Top-1 적중률은 바뀌지 않았지만 **모델의 신뢰도가 올라간다.**
AUC가 낮으면 SHAP 해석 자체를 의심해야 하므로 이 개선은 의미가 있다.

### 선택 2: 왜 권고 구간을 관측 범위 안으로 제한하나?

```python
        "current_min": float(result.X[feature].min()),
        "current_max": float(result.X[feature].max()),
```

한 번도 관측되지 않은 값에 대해서는 **모델이 근거 없이 외삽한다.**
"압력을 30까지 낮추면 좋다"는 결론이 나와도, 30을 본 적이 없다면
그건 데이터가 아니라 트리 구조의 부산물이다.

그래서 권고 구간을 관측 범위 안으로 제한하고, 그 사실을 결과에 명시한다.

### 선택 3: 왜 SHAP과 분포 비교를 둘 다 보나?

| | SHAP | 분포 비교 |
|---|---|---|
| 무엇을 설명하나 | **모델이 학습한 것** | **데이터 자체** |
| 상호작용 반영 | ✅ | ❌ |
| 모델 오류에 영향 | ✅ 받는다 | ❌ 안 받는다 |

둘이 일치하면 신뢰도가 크게 올라가고, 어긋나면 둘 중 하나를 의심해야 한다.
서로를 검증하는 관계다.

## 확인 문제

**1.** SHAP 1위가 `thickness_sigma`(두께 산포)로 나왔다. 이걸 개선안으로
"두께 산포를 줄이세요"라고 보고하면 무엇이 잘못인가?

<details><summary>정답</summary>

**두께 산포는 조작할 수 있는 값이 아니다.** 공정의 결과로 측정되는 값이다.

엔지니어가 장비에서 바꿀 수 있는 건 온도·압력·유량 같은 설정값이다.
"두께 산포를 줄여라"는 목표이지 조치가 아니다.

올바른 보고는 이렇다: *"두께 산포가 커진 것이 불량과 강하게 연관된다.
그 산포를 만드는 상류 요인은 서셉터 온도 편차이므로, 온도를 0.35 이하로 관리하라."*
</details>

**2.** AUC가 0.55인데 SHAP 1위가 명확하게 나왔다. 어떻게 해석해야 하는가?

<details><summary>정답</summary>

**믿지 말아야 한다.** AUC 0.55는 모델이 불량과 정상을 거의 구분하지 못한다는 뜻이다.

SHAP은 "모델이 어떻게 판단했는가"를 설명하는 도구다. 모델이 제대로 판단하지
못하고 있다면, 그 판단 근거를 아무리 정교하게 분해해도 노이즈를 분해한 것이다.

이럴 때는 ① 표본을 더 모으거나 ② 층화로 신호를 선명하게 하거나
③ 다른 스텝을 봐야 한다.
</details>

**3.** `_mean`, `_std`, `_min`, `_max`를 전부 피처로 넣으면 무슨 문제가 생기는가?

<details><summary>정답</summary>

네 값이 서로 강하게 상관되어 **SHAP 기여도가 분산된다.**

압력이 원인이라면 `chamber_pressure_mean`이 1위여야 하는데,
`_max`, `_min`이 기여를 나눠 가지면서 각각의 순위가 밀린다.
그러면 다른 파라미터가 1위로 올라와 진짜 원인을 놓칠 수 있다.

상관된 피처가 많을수록 SHAP 해석이 흐려지는 것은 일반적인 현상이다.
</details>

**4.** Cliff's delta를 평균 차이 대신 쓰는 이유 두 가지는?

<details><summary>정답</summary>

1. **이상치에 강건하다.** 순위만 보므로 극단값 하나가 결과를 좌우하지 않는다.
   FDC 데이터는 센서 오류로 튄 값이 섞이는 일이 흔하다.

2. **단위가 없다.** 파라미터마다 단위가 psi, degC, sccm으로 제각각이라
   평균 차이로는 서로 비교할 수 없다. Cliff's delta는 -1~1로 정규화되어 있다.
</details>

**5.** Scratch에서 `pad_life`가 1위로 나온 것을 어떻게 보고해야 하는가?

<details><summary>정답</summary>

**교락 가능성을 명시하고 상위 후보를 함께 보고해야 한다.**

`pad_life`는 톱니파라 시간과 직접 연관된다. 이상 사건이 특정 기간에 몰려 있으면
그 기간의 `pad_life` 값도 특정 구간에 몰리므로, 인과 없이도 상관이 생긴다.

보고 예: *"pad_life가 1순위로 나왔으나 이 변수는 시간과 직접 연관되어 교락
가능성이 있다. 2~3순위인 slurry_particle_count, slurry_flow가 물리적으로
스크래치와 더 직접 연결되므로 함께 확인할 것을 권한다."*

**물리적 타당성 검토가 통계를 보완해야 하는 대표적 사례다.**
</details>

## 더 알아보기

- **SHAP (SHapley Additive exPlanations)**: Lundberg & Lee (2017). 게임 이론의
  섀플리 값을 예측 기여도 분해에 적용. TreeSHAP은 트리 모델에서 정확해를 빠르게 계산한다
- **Cliff's delta**: Cliff (1993). 비모수 효과 크기. 0.147/0.33/0.474가 작음/중간/큼의 관례
- **매개변수(mediator) vs 교란변수(confounder)**: 계측값은 원인과 결과 사이의 **매개변수**다.
  매개변수를 통제하면 인과 효과가 사라져 보이므로, 인과 분석에서 다루는 방식이 다르다
- 관련 모듈: [`commonality.md`](commonality.md) — 여기서 찾은 챔버로 층화한다
