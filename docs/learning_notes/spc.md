# SPC 이상 탐지 — "언제부터 이상해졌나"

## 이 코드는 무엇을 하나

**입력**: 웨이퍼별 수율/패턴 라벨 + 검사 시각
**출력**: 이상 구간 목록 (`ALM-001 [EWMA] 03-05~03-12, 3.2σ`)

수율이나 불량률의 시계열을 감시하다가, 평소와 다르게 흘러간 **구간**을 자동으로 찾는다.

## 왜 이 단계가 필요한가

두 가지 이유가 있고, 두 번째가 더 중요하다.

**1. 조사 범위를 시간으로 좁힌다**
"수율이 떨어졌다"만으로는 어디를 봐야 할지 모른다. "3월 5일부터"를 알면
그 날짜 전후에 무엇이 바뀌었는지(부품 교체, 레시피 변경)를 뒤지면 된다.

**2. 다음 단계의 입력을 만든다** ★
커미널리티 분석은 "이상군 vs 정상군"을 비교하는 방법이다. 그 두 집단을 나누려면
먼저 이상 구간이 특정되어야 한다. **SPC가 없으면 M3 전체가 성립하지 않는다.**

## 핵심 로직

### 실패에서 시작하기 — 검출률 0%

처음 구현은 모든 지표에 평균±3σ 방식(individual chart)을 썼다.
Edge-Ring 불량률에 적용해 보니 이런 결과가 나왔다.

```
중심선 6.87%  σ=17.91  → 검출된 이상구간 0건
정답: 실제로 심어 둔 이상 사건 12건
검출률: 0/12 = 0%
```

σ가 중심선의 **2.6배**다. 관리한계가 `6.87 ± 3×17.91` = **-46% ~ +60%**가 되어
어떤 값도 벗어날 수 없었다.

### 원인 1: 지표의 성격에 맞지 않는 관리도 ★

진단해 보니 분포가 이랬다.

```
일별 집계 121일 중 0%인 날: 99일 (82%)
50%를 넘는 날: 3일 (최대 84%)
```

**불량률은 비율 데이터**다. 그리고 웨이퍼는 lot(25장) 단위로 함께 감염되므로,
어떤 날은 0%이고 어떤 날은 lot 하나가 통째로 걸려 84%가 된다.
이런 분포에 정규분포를 가정하면 σ가 터무니없이 커진다.

| 지표 | 성격 | 맞는 관리도 |
|---|---|---|
| 수율(%) | 연속값 | **individual** (평균 ± kσ) |
| 불량 발생률 | 비율 | **p-chart** (이항분포 기반) |

p-chart는 표본 수를 반영한다.

```python
    sigma_i = np.sqrt(p_bar * (1.0 - p_bar) / np.maximum(n, 1))
```

`n_i`가 분모에 있다. **표본이 적은 날은 관리한계가 넓고, 많은 날은 좁다.**
웨이퍼 10장으로 잰 불량률과 500장으로 잰 불량률은 신뢰도가 다르니 당연하다.

### 원인 2: baseline 오염

```
baseline 구간: 01-07 ~ 02-12 (앞 30%)
이 구간에 걸친 Edge-Ring 이상 사건: 3건
```

"앞부분은 정상일 것"이라고 가정했는데, 실제로는 그 구간에도 이상이 있었다.
관리도의 기준이 오염되면 σ가 부풀려져 진짜 이상을 놓친다.

p-chart는 전체 기간의 비율을 중심선으로 쓰므로 이 문제가 완화된다.

### 과분산과 Laney 보정

p-chart로 바꾸자 새 문제가 보였다. 이항분포가 예측하는 것보다 **실제 변동이 컸다.**

```python
        z = (p_i - p_bar) / np.maximum(sigma_i, 1e-12)
        moving_range = np.abs(np.diff(z))
```

표준화 잔차 `z`의 **이동범위**로 과분산 계수를 추정한다.

```
측정된 과분산 계수: 2.77
→ 이항분포가 예상하는 변동의 2.77배
```

원인은 명확하다. **lot 단위로 함께 움직이기 때문**이다. 한 lot이 감염되면
25장이 통째로 불량이 되므로, 독립적인 25번의 시행보다 변동이 훨씬 크다.

Laney의 p'-chart는 관리한계를 이 계수만큼 넓힌다. 보정하지 않으면 위양성이 폭증한다.

> 💡 **왜 표준편차가 아니라 이동범위인가?**
> 표준편차를 그냥 계산하면 이상 구간의 큰 값들이 포함되어 과분산이 실제보다
> 크게 추정된다. **연속한 두 점의 차이**는 점진적 이동에 둔감해서 순수한
> 단기 변동만 잡아낸다. 1.128은 이동범위 평균을 표준편차로 바꾸는 상수(d2)다.

### 원인 3: 사이클 타임 — 가장 놓치기 쉬운 함정 ★★

p-chart로 고친 뒤에도 검출률이 42%에 그쳤다. 놓친 사건을 하나씩 보다가 이걸 발견했다.

```
❌ EXC-0015 기간 12일 공격률 47%  해당구간 Edge-Ring   0장
❌ EXC-0022 기간  3일 공격률 75%  해당구간 Edge-Ring   0장
```

이상 사건 기간에 불량 웨이퍼가 **0장**이다. 말이 안 된다.

원인은 **시각 기준이 달랐다**는 것이다.

```
이상 사건 시각  = 공정 투입 시각 (fab_in_time)
SPC 집계 시각   = EDS 검사 시각 (eds_time)
                       ↑
                  66시간 차이
```

웨이퍼가 공정에 투입되어 EDS 검사를 받기까지 시간이 걸린다.
"3월 5일 EDS에서 불량이 급증"은 "3월 5일에 장비가 고장 났다"가 아니라
**"2.75일 전에 투입된 웨이퍼들이 무언가를 겪었다"** 는 뜻이다.

```python
    return alarm.start - cycle_time, alarm.end - cycle_time
```

보정 후:

```
검출률 42% → 83% (위양성 0건 유지)
```

> ⚠️ **실제 팹은 사이클 타임이 2~3개월이다.** 이 프로젝트는 66시간으로 단순화했지만,
> 현실에서는 "오늘 발견된 불량의 원인은 두 달 전에 있었다"가 된다.
> 이 보정을 빼먹으면 엉뚱한 기간의 설비 이력을 뒤지게 된다.

## 왜 이렇게 만들었나 — 설계 선택과 대안

### 선택 1: 왜 EWMA와 CUSUM을 둘 다 쓰나?

잡아내는 변화의 종류가 다르다.

| | 강한 것 | 약한 것 |
|---|---|---|
| **EWMA** | 비교적 큰 변화, 최근 추세 | 아주 작은 지속적 이동 |
| **CUSUM** | 작지만 꾸준한 누적 이동 | 급격한 일회성 변화 |

둘을 같이 돌리면 놓치는 이상이 줄어든다. 계산 비용이 낮아 함께 쓰지 않을 이유가 없다.

### 선택 2: 기본 파라미터를 어떻게 정했나 — 측정으로

```
  λ    k(σ)  검출률   위양성
 0.2   3.0    50%      0      ← 교과서 기본
 0.3   2.5    58%      0      ← 채택
 0.4   2.0    83%      0      ← 이 데이터에 최적이지만 과적합 위험
```

0.4/2.0이 가장 높지만 **채택하지 않았다.** 이 데이터셋의 사건 길이 분포
(5~13일)에 맞춘 값이라 실측 데이터에서도 최적일 보장이 없다.

0.3/2.5는 문헌에서 흔히 쓰이는 범위(λ 0.05~0.4) 안이면서 짧은 사건에 대한
반응성을 확보한 절충이다.

> ⚠️ **위양성 0건을 과신하면 안 된다.** 이 데이터는 121일 중 89일(74%)이
> 이상 구간이라 "정상 구간에서 잘못 울린 경보"를 판정할 여지 자체가 좁다.
> 실측 데이터에서는 위양성률을 다시 측정해야 한다.

### 선택 3: 왜 대조군을 '직전' 구간으로 잡나?

```python
    control_end = case_start
    control_start = control_end - pd.Timedelta(days=window)
```

전체 정상 웨이퍼를 대조군으로 쓰면 계절성·장기 추세·제품 변경 같은 시간 요인이
섞인다. **이상 구간 바로 직전**을 쓰면 그런 요인이 대부분 상쇄된다.

역학 조사에서 환자와 비슷한 조건의 사람을 대조군으로 고르는 것과 같은 발상이다.

### 선택 4: 왜 `split_by_pattern`도 함께 두나?

두 경로는 답하는 질문이 다르다.

| 경로 | 나누는 기준 | 무엇을 확인하나 |
|---|---|---|
| `split_case_control` | 시간 (SPC 경보 구간) | **실제 운영 상황** — 패턴을 아직 모르는 상태 |
| `split_by_pattern` | 패턴 라벨 | **분석 방법 자체의 성능** — 신호가 선명한 상태 |

SPC 경로는 이상 구간 안의 정상 웨이퍼도 이상군에 섞여 신호가 희석된다.
방법의 성능을 재려면 패턴 경로가, 실전 성능을 보려면 SPC 경로가 맞다.

## 확인 문제

**1.** 불량 발생률에 individual chart(평균±3σ)를 쓰면 왜 실패하는가?

<details><summary>정답</summary>

불량률은 **비율 데이터**이고, lot 단위 감염 때문에 0%와 높은 값 사이를 극단적으로
오간다. 이 프로젝트에서는 121일 중 82%가 정확히 0%였다.

정규분포를 가정해 표준편차를 계산하면 σ가 중심선의 2.6배까지 부풀려져,
관리한계가 -46%~+60%가 된다. 어떤 값도 벗어날 수 없어 검출률이 0%가 된다.

p-chart는 이항분포를 가정하고 시점별 표본 수를 반영하므로 이 문제가 없다.
</details>

**2.** 과분산 계수가 2.77이라는 것은 무슨 뜻인가?

<details><summary>정답</summary>

실제 변동이 이항분포가 예측하는 것의 **2.77배**라는 뜻이다.

원인은 lot 단위 클러스터링이다. 이항분포는 각 웨이퍼가 독립적으로 불량이 된다고
가정하는데, 실제로는 lot 하나가 감염되면 25장이 함께 불량이 된다.
독립 시행 25번보다 변동이 훨씬 크다.

보정하지 않으면 관리한계가 너무 좁아 정상 변동에도 경보가 울린다(위양성 폭증).
</details>

**3.** 사이클 타임 보정을 빼먹으면 실무에서 무슨 일이 생기는가?

<details><summary>정답</summary>

**엉뚱한 기간의 설비 이력을 뒤지게 된다.**

"3월 5일 EDS에서 불량 급증"을 보고 3월 5일의 장비 로그를 조사하면, 그때는
이미 원인이 지나간 뒤다. 실제 원인은 사이클 타임만큼 **앞선 시점**에 있다.

이 프로젝트에서는 66시간이라 검출률이 42%→83%로 바뀌는 정도였지만,
실제 팹은 2~3개월이라 보정 없이는 원인을 아예 찾을 수 없다.
</details>

**4.** 위양성 0건이라는 결과를 그대로 믿으면 안 되는 이유는?

<details><summary>정답</summary>

이 데이터는 전체 121일 중 **89일(74%)이 이상 구간**이다.
즉 아무 때나 경보를 울려도 74% 확률로 "적중"으로 판정된다.

"정상 구간에서 잘못 울린 경보"를 판정할 여지 자체가 좁으므로,
위양성 0건은 방법이 정확해서가 아니라 **채점이 관대해서**일 수 있다.
실측 데이터에서 다시 측정해야 한다.
</details>

- **d2 상수 (1.128)**: 이동범위 평균을 표준편차로 환산하는 계수. 부분군 크기 2일 때의 값
